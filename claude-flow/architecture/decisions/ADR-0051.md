## Context

Research features *Automatic fillers, plinths/toe-kicks, end panels and trim* (rank 14, value 4.6, P1; IKEA, Coohom)
and *Generated shared components* (value 4.5; Roomle, Coohom). ADR-0036 decided run-level filler, cover, plinth and
worktop. `suggestRunParts` in `src/core/project.ts` builds worktop, fillers and covers but **no run plinth**, because
every cabinet draws its own plinth (`cabinet.ts`, role `plinth`) and a run plinth would be doubled. N26 lists the
open gaps: no run plinth, no scribe allowance, sink false front not built.

## Decision

- **Run plinth.** For each run (same rule as today: floor base units side by side, gaps ≤ 150 mm) the suggestion adds
  one `RunPart` of kind `'plinth'`: the run length (covers included), the height and setback of the run's pieces,
  board = the pieces' body board. Pieces of that run get the optional project-item flag `plinthFromRun: true`; the
  project build leaves out their own `plinth` panels (cut list, sheets, 3D). Their carcass height is unchanged.
- **Different plinths in one run** (height or setback differ): no run plinth for that run, and a warning names the
  pieces and the values. Nothing is averaged (ADR-0008).
- **Scribe allowance.** A project setting *Scribe allowance for fillers and covers* (mm, default **0**). Each filler
  and the cover on a wall end is made that much wider; its reason says "gap 37 mm + 20 mm scribe". 0 keeps today's
  sizes. No value is invented (ADR-0010).
- **Sink false front.** A drawer front can be marked *Fixed front (no drawer)* in a cabinet space: the front panel
  stays, the drawer box and runners are left out, and the hardware schedule lists "front fixing — user-specified"
  (ADR-0010). Optional field on the space, absent = today's behaviour; no schema bump.
- Run parts stay listed with a reason, removable one by one, and undoable (ADR-0050).

## Alternatives considered

- **Keep piece plinths and add none at run level** (today) — a run of pieces has visible joints in the plinth and
  the paper's "Add plinth works like Add countertop" is not met.
- **Shorten each piece's plinth instead** — still one board per piece; does not give the single toe-kick users cut.

## Consequences

- Cut list: n piece plinths become one run plinth (split by the stock length if longer than a board, as worktops are).
- Removing the run plinth removes the `plinthFromRun` flags, so the pieces get their own plinths back.
