# ADR-0010: Edge banding (ABS) is an annotation on cut dimensions, not a dimensional allowance

## Context

Edge banding is applied after cutting. Some workshops shrink the cut size by the band thickness, others cut to
final size and let the band add; suppliers such as SALICE/Regency forms sometimes quote *finished* sizes that
include ABS. Mixing these conventions silently produces 1–2 mm errors across a cabinet.

## Decision

`Part.abs` records a band identifier (or `null`) per edge (`top/right/bottom/left`) **purely as an annotation**.
`width`/`height` are always the exact saw-cut size. The optimiser ignores ABS for placement; statistics only sum
band length per band ID (`edgeBandMm`). Any vendor input quoting ABS-inclusive finished sizes must be transformed
to cut sizes by an explicit, documented adapter rule (ADR-0026) — never inferred.

## Alternatives considered

- **Subtract band thickness automatically** — rejected: band thickness varies (0.4–2 mm) and the convention is workshop-specific.
- **Store both finished and cut sizes** — rejected for now: doubles the surface for inconsistency; may be revisited when a signed-off supplier mapping exists.

## Consequences

- CSV/XLSX columns `ABS_Top/Right/Bottom/Left` are labels, not numbers.
- The UI hides ABS under "advanced" because it does not affect the layout.
- `evidence/unknowns.md` keeps the ABS-inclusive supplier policy as an open item.

## Evidence (repository files)

- `src/engine/types.ts` — `EdgeBanding = Record<EdgeName, string|null>`; `Part.abs`.
- `src/engine/optimize.ts` — `edgeBandMm` accumulation only.
- `docs/architecture.md` — "All four ABS edges are annotations on cut dimensions, not dimensional allowances. Part width/height are exact cut sizes in millimetres."
- `docs/data-format.md` — CSV header with `ABS_*` columns.

## Compliance check

`grep -n "abs" src/engine/guillotine.ts src/engine/geometry.ts` returns nothing — placement code never reads ABS.
