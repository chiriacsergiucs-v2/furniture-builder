# ADR-0029: The catalog is fed by a scheduled, PR-gated offline reconstruction job

## Context

The catalog (ADR-0027) needs real products. The user asked for a scheduled job that reconstructs furniture from
manufacturers' public assembly manuals (IKEA first; BILLY 800 × 280 × 2020 mm as the benchmark) and feeds the
catalog. The app must stay a static offline PWA with no remote AI or runtime requests (ADR-0002).

## Decision

- **Authoring time, not run time.** Reconstruction happens in a scheduled Claude Code routine working on the
  repository. Its output is plain design documents committed under `src/catalog/entries/<catalogId>.json`; the app
  only ships and reads them. The app never contacts a manufacturer, a model or a server.
- **Gate: a pull request.** Each run works on branch `claude/catalog-feed`, keeps one open PR, never pushes `main`.
  An entry reaches users only after a human merges it and the site is deployed (pushed ≠ merged ≠ deployed).
- **Native products only.** An entry must be a valid `Design` using the existing roots (cabinet, desk, corner) and
  the space tree, built by `buildModel()` with zero errors. A product that cannot be represented without distorting
  it (bed frames, angled or curved parts, constructions the space tree cannot express) is **not** added; it is
  listed in `src/catalog/skipped.md` with the reason. An imported-assembly product root is out of scope until a
  separate ADR approves it.
- **No invented facts (ADR-0010).** Dimensions come from the manual's printed values or the manufacturer's
  published product dimensions; every value used goes into the entry's `evidence` sidecar
  (`src/catalog/entries/<catalogId>.evidence.json`): value, source (page, printed label or product-page field),
  status `identified` / `geometrically resolved` / `manufacturing verified` (three states, never a percentage), and
  the fields left unresolved (e.g. board thickness when not printed). Unresolved values that the model needs are
  filled with the app's defaults **and listed as unresolved**; the card and editor show *Dimensions not verified for
  cutting* for any entry with unresolved fields.
- **Hardware** found in the manual is recorded in the evidence file with its printed quantity; the app's hardware
  schedule stays its own guidance (ADR-0010) until a hardware ADR maps documented hardware into the model.
- **No copyrighted material in the repo.** No PDFs, page images or traced drawings are committed; only measured
  facts, part counts, the public `sourceUrl` and article number. Brand names are used only to identify the source.
- **Revisions.** Changing a shipped entry bumps its `revision`; copies keep the revision they were taken from
  (ADR-0028). Entries are never deleted once shipped, only marked withdrawn, so `origin` links never dangle.
- **Verification per run:** `npm run lint && npm run typecheck && npm test && npm run build` plus
  `python3 -I claude-flow/scripts/validate.py`; a test asserts every entry validates, builds without errors and has
  an evidence file covering its overall width, height and depth.

## Alternatives considered

- **Browser PDF importer that users run themselves** — a separate feature; not required to feed the catalog and
  not decided here.
- **Fetch the catalog from a remote source at runtime** — rejected by ADR-0002.
- **Commit the manuals for reproducibility** — rejected: third-party copyright; the URL is the reference.
- **Auto-merge job output** — rejected: unreviewed manufacturer data would ship as fact.

## Consequences

- The catalog grows only as fast as PRs are reviewed.
- Some products cannot enter until the model grows (beds, irregular parts); `skipped.md` makes the gap visible.

## Evidence (repository files)

- Nothing implements this yet. The routine is configured outside the repository (Claude Code routine
  "Furniture catalog feed", weekly).

## Compliance check

When accepted: `src/catalog/entries/` exists; the catalog test passes for every entry; no `.pdf`/image file under
`src/catalog/`; `git log main` shows feed commits only via merged PRs.

## Open questions (defaults used until answered)

1. Cadence — default weekly, Monday 08:39 Europe/Bucharest, at most 2 new entries per run.
2. Brands beyond IKEA — default IKEA only until the user names others.
