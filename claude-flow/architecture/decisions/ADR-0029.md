## Context

Earlier iterations marked work done because a mock existed or an AI reply claimed completion. The user introduced
two ledgers — `docs/progress.json` (STEP_00–14, gates G1–G10) and `docs/modular-engine-backlog.md` (B00–B31) — with
strict status semantics.

## Decision

Status values are **Done / Partially done / Not done / Dropped** (B-ledger) and `pending / implemented_unverified /
verified_partial / verified` (STEP ledger). Moving to Done/verified requires a path or commit plus the smallest
applicable verification run, cited inline. IDs are never renumbered or deleted; deprecated items become Dropped
with a reason. Every code iteration updates the ledger in the same change and the reply includes the B-ID table.
Release claims require the full sequence `npm ci && npm run lint && npm run typecheck && npm run test:kernel &&
npm run test && npm run build && npx playwright install --with-deps chromium && npm run test:e2e` plus the
`Deploy GitHub Pages` run, and CI runs are cited by run ID. CI results quoted from docs are "reported", not
"re-executed", unless the agent ran them.

## Alternatives considered

- **Single TODO file** — rejected: the user mandated one canonical ledger per concern to stop proliferation.

## Consequences

- `delivery/backlog.json` and `delivery/milestones.md` in this folder are *mirrors* of the repo ledgers and must be regenerated, not edited independently (`scripts/validate.py` flags drift).
- The lockfile must be regenerated by `lockfile.yml` before CI/deploy success is claimed after a dependency change.

## Evidence (repository files)

- `docs/modular-engine-backlog.md` §"Status semantics", §"Execution protocol".
- `docs/progress.json` — `milestones[].status`, `gates`, `sourceOfTruth`.
- `AGENTS.md` §"Verification sequence", "Never claim unrun tests or deployment success", "Lockfile must be regenerated by GitHub Actions before declaring CI or deployment success."
- `docs/verification-log.md`.

## Compliance check

`python3 -I claude-flow/scripts/validate.py` reports no ledger drift; last cited CI run ID resolves in `docs/`.
