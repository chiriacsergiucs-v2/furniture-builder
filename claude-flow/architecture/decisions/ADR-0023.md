# ADR-0023: Presets carry an immutable source pin; revision advances only on explicit Save; inserts are copy-on-write

## Context

A part inserted from a preset must remember where it came from (for re-sync and audit) without being mutated when
the library preset is later edited, and editing a preset draft must not touch storage until the user saves.

## Decision

`PresetOrigin` pins `{presetId, revision, definitionId/version, templateId/version}` on inserted parts and
assemblies. `savePreset` increments `revision` on explicit Save only. *Customize for project* edits an isolated
copy and inserts on explicit action; *Duplicate* creates a fresh-ID draft that calls storage only on *Save duplicate*.
Library edits never propagate into projects automatically.

## Alternatives considered

- **Live links from parts to presets** — rejected: a library edit would silently change a project already cut.
- **Auto-save drafts** — rejected: creates half-edited presets and revision noise.

## Consequences

- `sourcePreset` is optional and absent on manual/legacy parts; validators accept both.
- Revision history is also journaled in the `revisions` table (ADR-0003).

## Evidence (repository files)

- `src/presets/origin.ts` — "Immutable reference to a saved preset revision. Missing on legacy/manual parts."
- `src/presets/customize.ts`, `src/presets/duplicate.ts`, `src/components/PresetCustomization.tsx`.
- `docs/handoff.md` — "Duplicate action creates a fresh-ID draft and does not call storage until Save duplicate"; B19 Done.
- `src/tests/unit/preset-customization.test.ts`.

## Compliance check

Test: insert preset into two projects, edit one, assert the other project and the library preset are unchanged.
