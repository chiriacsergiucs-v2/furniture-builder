## Context

The user continues some designs in Autodesk Fusion. Native .f3d is closed; STEP needs a CAD kernel the browser does
not have. Every part is already an axis-aligned box (ADR-0004), which a Fusion script can recreate exactly.

## Decision

Export a self-contained Python script for the Fusion API that creates one named component per panel (label +
panel id), each a solid box from `Panel.box`, converting millimetres to Fusion's centimetres only in the exporter.
Materials become appearance names; hardware is written as a comment table. The script is generated from
`FurnitureModel` only. The UI and README say **"not verified inside Fusion"** until the user runs one and reports the
result.

## Alternatives considered

- **STEP via a WASM CAD kernel** — large download and licensing questions.
- **OBJ / glTF mesh** — Fusion imports meshes, but the user needs editable solids.

## Consequences

- A Python syntax check (`py_compile`) runs in tests; real execution needs the user's Fusion.
- Desk and cabinet export the same way; no product-specific code.

## Evidence (repository files)

- `src/core/types.ts` — `Panel.box`, `label`, `id`.
- `src/core/build.ts` — `buildModel`.

## Compliance check

When accepted: generated script passes `python3 -m py_compile`; component count equals `model.panels.length`; the
export button's text includes "unverified".

## Answers (2026-10-21, from the user)

- **Grouping:** one Fusion component per piece with sub-components — carcass, each drawer (box + front), doors —
  each containing one body per panel.

This ADR becomes **Accepted** when the code exists and its compliance check passes.
