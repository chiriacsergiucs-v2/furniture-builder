# ADR-0022: Legacy component trees are reconstructed read-only in memory; stored rows change only on explicit user Save

## Context

Projects and presets saved before the component engine (B01–B16) hold `cabinetSpec`/`drawerSpec` without a
`componentTree`. Rewriting those Dexie rows on load would be a silent, irreversible migration of user data.

## Decision

`adaptLegacyProject` / `adaptLegacyPreset` deterministically build the component tree **in memory** from known
historical specs when a record is read. The original IndexedDB row is untouched until the user explicitly saves.
Unknown or invalid legacy shapes are passed through unchanged, never discarded. Legacy project/preset JSON backup
formats remain readable and exportable.

## Alternatives considered

- **One-off batch migration on first load** — rejected: same risk profile as ADR-0004 but without the user's awareness; a generator fix later could not be re-applied.

## Consequences

- Adapters must be pure and idempotent; applying twice equals applying once.
- A future record `schemaVersion` bump still ships the v1 adapter.

## Evidence (repository files)

- `src/furniture/legacy-adapter.ts` — "Recover only known legacy cabinet/drawer graphs. Missing or invalid data is never discarded."; "Pure in-memory adapter. The original IndexedDB record is not modified on read."
- `docs/handoff.md` §"2026-10-11 — B19/B20" — "original Dexie records remain unchanged until explicit user Save".

## Compliance check

Unit test reads a legacy fixture, resolves a tree, re-reads the DB row and asserts deep equality with the fixture.
