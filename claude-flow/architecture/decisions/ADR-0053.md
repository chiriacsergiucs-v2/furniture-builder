## Context

Research feature *Catalogue-led ensemble workspace* (value 4.5, P0; IKEA). The paper's workflow: open the
workspace, choose a category, **drag a template into the scene** to create an instance. The app already has the
catalog part: *Add a piece* lists every catalog item grouped by room or type with search, and the Catalog page adds
items to the open project (`src/ui/Catalog.tsx`, `addPiece`). What is missing is choosing **where**: `makeItem`
always places the new piece to the right of the existing ones (`src/core/project.ts`), and it is then moved with
mm fields.

## Decision

- After choosing an item in *Add a piece* (or *Add* on the Catalog page with a project open), the project opens on the
  **Plan** with a banner **"Tap the plan to place <name>"** and buttons *Place to the right* (today's behaviour) and
  *Cancel*.
- A tap/click on the plan places the piece's left-back corner at that point, in whole mm, on the floor (or the
  wall-height for wall-hung pieces, ADR-0031), clamped to x ≥ 0 and z ≥ 0. While the pointer moves, an outline of the
  piece's footprint follows it (desktop).
- If the piece would overlap another, it is placed anyway and the existing `pieces-overlap` error shows, as with a
  typed position (ADR-0008).
- One placement = one undo step (ADR-0050).

## Alternatives considered

- **Drag and drop from the dialog onto the plan** — does not work well on phones (dialog covers the plan) and needs
  a drag library or custom pointer handling across two surfaces; tap-to-place gives the same result on every width.
- **Brand facet** (the earlier gap of N14) — belongs to ADR-0029's feed, not to this feature.

## Consequences

- Precise numbers remain available after placing (*From left*, *From back*).
- Snapping to neighbours is not part of this ADR (connector work, not scheduled).

## Evidence (repository files)

- Unit test: placing at plan point (1234, 456) stores position x 1234, z 456, y 0 (or the wall height).
- Find-it at 1440 and 375 px: create a project → **Add a piece** → choose an item → banner text **Tap the plan to
  place** visible → tap the plan → *From left* shows the tapped value (± 1 mm of the scale).
- `npm run lint && npm run typecheck && npm test && npm run build`.

## Questions and answers (2026-10-24; recommended answers auto-accepted on the user's instruction)

1. *Drag-and-drop or tap-to-place?* — **Tap-to-place (works on phone and desktop); drag not built.**
2. *Keep the old automatic "to the right" placement?* — **Yes, as the *Place to the right* button.**
3. *Allow placing on top of another piece?* — **Yes; the overlap error shows, as with typed numbers.**

## Implementation (2026-10-24)

Store `placingItemId` set by `addPiece`; `placeAt`/`stopPlacing`; banner **Tap the plan to place …** with *Place to the right* and *Cancel* (Cancel = undo of the add, ADR-0050); the plan maps the tap to room mm via the SVG matrix and shows the footprint outline while the pointer moves; the view switches to Plan. Tests: `tests/project-undo.test.ts` (tap-to-place). find-it `tools/ensemble/find-it-adrs.mjs` (production build, bare app, visible text, 1440 and 375 px): 60/60: tapped piece at From left ≈ 2000.
