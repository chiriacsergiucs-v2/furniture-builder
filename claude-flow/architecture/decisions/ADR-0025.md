## Context

The user wants to continue design work in Autodesk Fusion. Native `.f3d` is proprietary; STEP export needs a CAD
kernel the browser does not have.

## Decision

`exportFusionPython(project, assembly)` emits a Python script for the Fusion API that creates one named B-rep solid
per positioned instance (direct modelling, cm conversion at the boundary). It does not export STEP/F3D and has
**not been executed inside Fusion by this project's CI or agents**. Documentation and agent reports must say
"unverified in Fusion".

## Alternatives considered

- **STEP via a WASM CAD kernel** — rejected: dependency weight and licensing; may be revisited.
- **Mesh export (OBJ/glTF)** — rejected for Fusion: the user needs editable solids, not meshes.

## Consequences

- TSK-008 (run the script in Fusion) is blocked on access to a Fusion runtime; until then the feature is labelled as a snapshot.
- Fusion units are centimetres; conversion happens only in `fusion.ts` (ADR-0007).

## Evidence (repository files)

- `src/assembly/fusion.ts` — "Fusion 360 Python script: real, separately named solid B-rep components, not mesh."
- `AGENTS.md` — "Fusion export is Python API source for static direct-model B-reps, not native .f3d/.step. Never claim verified inside Autodesk Fusion."
- `docs/handoff.md` — "Execution in Fusion itself remains unverified."

## Compliance check

Generated script parses with `python3 -m py_compile`; README copy contains "unverified" next to the Fusion feature.
