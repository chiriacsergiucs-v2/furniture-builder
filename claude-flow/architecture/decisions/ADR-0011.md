## Context

2-D guillotine cutting-stock is NP-hard. A workshop user needs a good layout in about a second on a phone, and the
same input must give the same output so that a saved result can be trusted and tests are reproducible.

## Decision

The engine runs repeated greedy constructions over seeded orderings (xorshift PRNG from `settings.seed`), three
fit heuristics (`area`, `short`, `long`) and both split orders (`vertical-first`, `horizontal-first`), bounded by
`maxRestarts` and `maxDurationMs`. Results are compared **lexicographically**: fewer unplaced instances → fewer
new stock sheets → less unrecoverable waste → more recoverable area → fewer cuts, with a stable string tiebreak.
The result records `search.{attempts, elapsedMs, seed, strategy}`. The UI and docs state it is a heuristic and
**not a global optimum**; agents must never describe it otherwise.

## Alternatives considered

- **Exact MIP/branch-and-bound** — rejected: unbounded runtime in the browser; no solver dependency allowed (ADR-0002).
- **Single weighted cost function** — rejected: weights hide the user's real priority order (place everything, then save sheets); lexicographic order is explainable.
- **Non-deterministic `Math.random`** — rejected: irreproducible results and flaky tests.

## Consequences

- Changing the objective order is a product decision, not a tuning tweak; it needs change control.
- `defaultSettings()` (kerf 4, 18 restarts, 1500 ms, seed 42, min offcut 150×150 / 40 000 mm²) are defaults, not constants; they are validated per project.
- Benchmarks in `tests/benchmark.mjs` track regressions in utilisation and runtime.
