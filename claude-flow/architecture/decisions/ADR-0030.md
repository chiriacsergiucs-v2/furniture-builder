## Context

No `claude-flow` or `ruflo` package is declared in `package.json`, there is no `.claude/` or `.claude-flow/`
scaffold in the repository, and no CLI version is recorded anywhere. Translating these contracts into a specific
runtime's schema before that is known would produce files that do not load.

## Decision

`claude-flow/agents/*.md`, `workflows/*.md` and `tasks/tasks.json` are **plain, version-neutral contracts** (role,
inputs, outputs, gates, never-do rules). They are consumed by reading, not by a runtime. TSK-001 pins a runtime:
record the version, run its `init` in a disposable worktree, inspect the generated schema, translate, validate
with its CLI, and only then commit native files. Until then no agent claims the folder is "installed".

## Alternatives considered

- **Guess the latest Ruflo schema** — rejected: schema drift across versions; unverifiable here.
- **Convert to Claude Code `.claude/agents/`** — offered to the user; the user chose to fix this folder in place.

## Consequences

- This ADR flips to Accepted (with the version recorded) when TSK-001 closes; `manifest.json.runtime` mirrors it.

## Evidence (repository files)

- `package.json` — no `claude-flow`/`ruflo` dependency.
- Repository root listing — no `.claude*` directory (checked 2026-10-21).

## Compliance check

`grep -ri "ruflo\|claude-flow" package.json` is empty **and** `manifest.json.runtime.version` is `null` ⇒ status stays Proposed.
