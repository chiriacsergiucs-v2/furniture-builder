## Context

The interface had tokens but no scale, eight button styles, no grouping in the inspector, no dark theme and no
primitive for guided (wizard-like) flows that the catalog work (ADR-0027) will need. The save-failure status was
hidden on phones. Full audit in `docs/ui-design.md`.

## Decision

- All colours, type sizes, spacing, radii, shadows and motion are custom properties on `:root` (`src/styles.css` §1);
  dark values come from `prefers-color-scheme` or `data-theme` on `<html>`; print always uses the light set.
- The theme choice lives in `localStorage` only (`fb:theme`); no telemetry, no network (ADR-0002).
- Components are CSS classes plus the small React controls in `src/ui/controls.tsx`; screens use only these.
- A `Steps` rail is the one primitive for staged flows: here a section map of the piece (size → inside → build →
  boards → cut) with live status; a guided flow sets `aria-current="step"` and adds `.wizard-footer`. Nothing is gated:
  frequent paths keep their length.
- Drawings and the 3D canvas take their colours from tokens; text on material-coloured fills stays dark in both
  themes. Geometry stays in `buildModel()` (ADR-0004).

## Alternatives considered

- **A CSS framework or component library** — rejected: a dependency for no gain, and it would not know Barlow numerals
  or the tape / mat palette.
- **Dark theme only via `color-scheme`** — rejected: the drawings and the dark top bar need explicit values.

## Consequences

- Error diagnostics keep their colours and are never hidden (ADR-0008); they gained icons.
- Native `confirm()` dialogs remain (open question in `docs/ui-design.md`).

## Evidence (repository files)

- `src/styles.css`, `src/ui/controls.tsx`, `src/ui/icons.tsx`, `src/ui/useTheme.ts`, `src/ui/Templates.tsx`,
  `docs/ui-design.md`.

## Compliance check

`grep -c "#[0-9a-f]\{6\}" src/ui/*.tsx` finds colours only in the exported-SVG stylesheet in `App.tsx` and the
default colour of a new material in `Dialogs.tsx`; everything else resolves through `var(--…)`.

## Answers (2026-10-23, from the user)

From `docs/ui-design.md` open questions:
1. **Replace native confirm()/prompt()** with the app's own dialog — built: `src/ui/Confirm.tsx` (`askConfirm`, `askText`), every call site switched.
2. **Theme toggle stays in the top bar.**
3. **No guided New flow**; *Start from* (every catalog item) is the quick start.
4. **Bottom action bar on phones** — built: at ≤ 760 px the actions sit in a fixed bottom bar (safe-area aware); the page reserves its height.
Evidence: find-it acceptance at 1440 / 1024 / 390 / 360 px (actions in the top bar on desktop, bottom bar on phones; delete asks in the app's own dialog, Cancel keeps the piece). Not checked on a real phone or with a screen reader.
