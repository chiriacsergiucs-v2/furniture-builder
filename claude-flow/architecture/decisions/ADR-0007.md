## Context

Panel saws, edge banders and supplier order forms work in whole millimetres. Floating-point widths cause
non-conserving area sums and off-by-one kerf errors; unit mixing (cm in Fusion, m in 3D) caused real confusion in
early iterations.

## Decision

Every board, part, offcut, trim, kerf and placement dimension is a **non-negative safe integer in millimetres**
(`type Mm = number` guarded by `integer()` in `schema.ts`). Validation rejects any non-integer. Conversions to
other units (centimetres for Fusion, metres for three.js) happen **only at the export/render boundary** and never
write back. Assembly positions are integer mm and rotations integer degrees.

## Alternatives considered

- **Decimal mm with tolerance** — rejected: tolerance comparisons spread through every geometry routine and the validator's conservation check (`gross = parts + trims + kerf + recoverable + unrecoverable`) would no longer be exact.
- **Branded numeric type** — considered; a plain alias plus runtime validation was chosen to keep JSON backups trivially readable.

## Consequences

- UI inputs must coerce/validate to integers before saving; invalid projects are rejected by `validateProject`, not silently rounded.
- Supplier dimensions that include edge-banding allowances (ABS-inclusive) must be transformed to cut sizes by an explicit, reviewed rule before entering the model (ADR-0010, ADR-0026) — never by rounding on import.

## Evidence (repository files)

- `src/engine/types.ts` — `export type Mm = number // validated positive/zero integer millimetres only`.
- `src/engine/schema.ts` — `integer()` uses `Number.isSafeInteger`; `validateProject` applies it to every dimension and setting.
- `src/engine/schema.ts` — assembly pieces: `rotationDeg` must be safe integers.
- `docs/data-format.md` — "All board/part/cut dimensions are integer millimetres."
- `AGENTS.md` — "Exact integer millimetres"; "Per-instance XYZ positions are integer millimetres; rotations are integer degrees."

## Compliance check

`src/tests/unit/schema.test.ts` includes a rejection case for a non-integer width; `validateResult` area conservation holds exactly (no epsilon) on all fixtures.
