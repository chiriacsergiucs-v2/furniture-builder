## Context

Research feature *Derived-component dependency regeneration* (rank 23, value 4.2, P1 internal; Roomle, Coohom).
Run parts are stored with their room position when suggested (`RunPart` in `src/core/project.ts`). When a piece
moves or is resized they become wrong; the app then reports `run-part-overlap` ("suggest the run parts again after
moving pieces") and the user must press *Suggest again*, which also brings back parts they had removed.

## Decision

- **Each run part records its sources:** `from: string[]` (item ids of the run) and a stable `key` = kind + the
  sorted source ids + end/gap position (e.g. `filler|a,b`, `cover-left|a`).
- **Automatic refresh:** project setting *Keep run parts up to date* (on once run parts were suggested). After every
  project change that touches pieces (move, resize via *Back to project*, add, remove, turn, merge), run parts are
  suggested again **inside the same commit**, so it is one undo step (ADR-0050).
- **User removals are overrides:** removing a run part stores its `key` in `runPartsRemoved`; refresh never brings
  it back while its sources exist. *Suggest again* clears the removals after a confirmation.
- **Only affected runs change:** parts whose `key` and box are unchanged keep their id; the list says
  "Worktop updated: 2400 → 3000 mm" for parts that changed, once.
- Turning the setting off keeps today's behaviour (stored parts, overlap error, manual *Suggest again*).

## Alternatives considered

- **Full dependency graph for every derived value** — the only derived parts today are run parts; a graph is
  premature.
- **Recompute run parts on every render, never store them** — loses user removals and the stored board copy.

## Consequences

- `run-part-overlap` disappears in normal use; it stays for the "off" setting.

## Questions and answers (2026-10-24; recommended answers auto-accepted on the user's instruction)

1. *Automatic by default?* — **Yes, once run parts were suggested; a setting turns it off.**
2. *Keep the user's removals?* — **Yes, until *Suggest again* (with confirmation).**
3. *One undo step for a change and its refresh?* — **Yes.**
