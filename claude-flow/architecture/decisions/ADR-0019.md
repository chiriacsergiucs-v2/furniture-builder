## Context

Nesting needs, per material, the sheet size, how many are available, edge trim, and the saw kerf. Today a
`Material` has only name, thickness, grain and colour, and the design document is `schemaVersion: 1` (ADR-0011).

## Decision

Extend `Material` with optional `sheet: { length, width, trim, count | null }` (integer mm; `count: null` =
unlimited) and add `cutting: { kerf, minOffcut }` to the design. Bump the design document to `schemaVersion: 2`.
`validateDesign` keeps accepting version 1 and upgrades it **in memory** with defaults (2800 × 2070 mm sheets for
18 mm board, 4 mm kerf); the stored row is rewritten only when the user next edits that design. Sheet length runs
along the grain, matching cut-list length (ADR-0009).

## Alternatives considered

- **Separate global stock library** — useful later for a whole workshop, but makes a design file depend on
  external data; kept for the multi-piece project work (ADR-0022).
- **Hard migration of stored rows on startup** — rejected: rewrites user data the user has not touched.

## Consequences

- Old design files keep opening; new files need the new app.
- Materials dialog gains sheet fields.

## Evidence (repository files)

- `src/core/types.ts` — `Material`, `Design.schemaVersion: 1`.
- `src/core/design.ts` — `validateDesign`, `defaultMaterials`.
- `src/persist/db.ts` — rows are whole design documents.

## Compliance check

When accepted: a test loads a version-1 design, validates it, builds it, and exports it as version 2 with identical
panels.

## Open questions (must be answered before this becomes Accepted)

- Which sheet sizes do you buy for each board (PAL 2800 × 2070? MDF 2800 × 2070 or 2440 × 1220?)
- Typical trim per edge on factory sheets?
