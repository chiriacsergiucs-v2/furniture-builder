# ADR-0005: Versioned Dexie schema that retains every historical version declaration

## Context

Dexie upgrades a user's database by replaying `version(n).stores(...)` declarations in order. Removing an old
declaration breaks upgrades from that version. Browser updates and reinstalls must not lose data.

## Decision

`FurnitureDatabase` declares **every** schema version ever shipped (currently v1 and v2) and increments
`DATABASE_SCHEMA_VERSION` for any index/table change. Upgrades are expressed as `.upgrade(tx => …)` callbacks that
only back-fill missing fields (e.g. `categoryId = 'uncategorized'`). Three version numbers are deliberately kept
independent: Dexie DB schema version, per-record `schemaVersion` (currently 1) and JSON backup `schemaVersion`
(currently 1).

## Alternatives considered

- **Single rolling schema declaration** — rejected: breaks upgrades for users on older versions.
- **Couple record and DB versions** — rejected: index changes would force record rewrites and backup-format churn.

## Consequences

- Adding a table or index = new `version(N+1)` block + constant bump + focused `db.test.ts` case; never edit an existing version block.
- Changing a persisted record shape = bump record `schemaVersion`, keep readers for old versions (ADR-0006, ADR-0022).
- Deep mapped types across the Dexie boundary are avoided (`StoredComponentTree` is a shallow boundary) to keep Dexie's type recursion tractable.

## Evidence (repository files)

- `src/db/database.ts` — `DATABASE_SCHEMA_VERSION=2`, `this.version(1).stores(...)`, `this.version(2).stores(...).upgrade(...)` with the comment "Retain old schema declarations. Future changes must increment Dexie's version."
- `docs/storage-migration.md` — "Dexie versions 1 and 2 retained… Internal record schema version 1 is independent of Dexie DB schema and full-JSON-backup schema version 1."
- `src/furniture/component-engine.ts` — "Shallow boundary prevents Dexie's deep mapped-type recursion."

## Compliance check

Number of `this.version(` calls in `database.ts` equals `DATABASE_SCHEMA_VERSION`; no existing `stores({...})` literal differs from its last committed form (`git log -p src/db/database.ts`).
