# ADR-0036: Kitchen modules: tall units, construction flags on the cabinet root, appliance niches and run-level parts

| | |

## Context

Kitchen cabinets get the most variants (ADR-0033). Research (2026-10-22, unverified) found that about 80 % of EU
kitchen modules are one carcass with a different front split and interior — those build today — while sink bases,
appliance housings, dishwasher spaces, hood units and run "glue" parts (fillers, cover panels, plinth, worktop) need
construction Mobila lacks. The parts retail planners most often leave out are exactly the glue parts.

## Decision

- **Tall cabinet** is a family on the existing cabinet root (height up to 2400 mm); no new code beyond templates.
- **Construction flags on `CabinetParams`** (optional, absent = today's behaviour, no schema bump):
  - `topKind: 'panel' | 'rails'` — two front/back rails (default 100 mm deep) instead of a full top (sink base,
    under-worktop units);
  - `back: 'none'` already exists; add `backCutout` only via a later ADR (non-box);
  - `bottom: 'none'` — for over-hood wall units.
- **Appliance niche** = an `empty` space with `appliance: { kind, niche: { w, h, d } }` entered by the user from the
  appliance installation drawing. Mobila never defaults niche sizes; the niche is checked against the opening
  (error if it does not fit) and listed as a hardware-schedule line "appliance — per its drawing".
- **Front-only element** (`panel` product, a new tiny root): an integrated dishwasher/fridge door or a cover panel —
  one front-material panel with handle holes, no carcass; fixing hardware user-specified.
- **Run-level parts belong to projects** (ADR-0022, ADR-0031): along a run of floor pieces the project can add
  *filler* (gap width + scribe allowance setting), *end cover panel* (exposed sides), *plinth* (run length, setback)
  and *worktop* (run length, depth, thickness, joints at corners). Each is a project-level panel in the combined cut
  list with its reason ("filler — gap 37 mm + 20 mm scribe"). *Fill run* proposes widths from the family width grid
  with the remainder as a filler.
- Lift-up flaps, carousels, U-cut sink drawers, pull-out frames and waste systems are `requires: ['hardware:user']`
  (and the U-cut is also non-box); they stay greyed until hardware data exists (ADR-0010).

## Alternatives considered

- **A separate kitchen root with its own carcass code** — rejected (ADR-0007: reuse `buildCabinet`).
- **Default appliance niche sizes** — rejected: they differ per model; inventing them violates ADR-0010.

## Consequences

- 10 kitchen families, 38 variants (`docs/catalog.md`); 23 build today, the rest unlock with these flags and ADR-0037.
- The fuzz generator must pick the new flags.

## Evidence (repository files)

- `src/core/cabinet.ts` (carcass, `mount`, `bottom`), `src/core/corner.ts`, `src/core/project.ts` (`resolvePlacements`,
  gaps), `src/core/types.ts` (`CabinetParams`).

## Compliance check

When accepted: tests for rails-top (no top panel, two rails, no overlap), niche fit error, front-only element in the
cut list, and a 3-piece run whose filler, cover panel, plinth and worktop appear once each with a reason; fuzz covers
`topKind` and `bottom: 'none'`.

## Open questions (defaults used until answered)

1. Default plinth for kitchen families — 100 mm (default) or 150 mm?
2. Carcass height 720 mm (IKEA-style, default) or 780 mm (German makers)?
3. Scribe allowance on fillers — default 20 mm.
