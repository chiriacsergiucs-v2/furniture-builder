## Context

Research feature *Transactional undo/redo* (paper rank 9, value 4.7, P0; Roomle). Undo/redo exists for the piece
editor only (F15): `commit` in `src/store/designStore.ts` keeps `past`/`future` of the `Design`. Every project change
goes through `commitProject` (same file), which keeps no history, and the Undo/Redo buttons are hidden while a project
is open (`{!inProject && …}` in `src/ui/App.tsx`). Adding, removing, moving, turning, gaps, placement, merging
(ADR-0047) and run parts (ADR-0036) therefore cannot be undone; removing a piece and merging only ask for confirmation.

## Decision

- **A project history** beside the piece history: `projectPast: Project[]`, `projectFuture: Project[]`, at most 100
  snapshots (same limit as `HISTORY`). `commitProject` pushes the previous project and clears the future.
- **One user action = one step.** Every store action calls `commitProject` exactly once, so a compound action —
  merge, *Suggest worktop, fillers and covers*, a gap change that moves the pieces on the right, a scope-wide finish
  (ADR-0052), an automatic run-part refresh (ADR-0058) — undoes as one step. Typing in a mm field commits on blur or
  Enter, as today, so one edited value is one step.
- **Editing a piece inside a project** (*Edit this piece*): its edits use the piece history as today. *Back to project*
  records the piece's before/after as **one** project step, so undo in the project restores the piece as it was.
- **Buttons and keys:** Undo/Redo are shown in the project too (same buttons, Ctrl+Z / Ctrl+Shift+Z); they act on the
  project history when the project is shown and on the piece history while a piece is edited.
- **Not persisted:** history lives in memory for the open session, like the piece history. Opening another project or
  piece clears it.
- Confirmations for *Remove* and *Merge* stay, but their text no longer says "cannot be undone".

## Alternatives considered

- **Command log with inverse operations** — more code for the same result; snapshots are cheap (projects are small
  JSON documents with embedded designs) and cannot get an inverse wrong.
- **One history for pieces and projects** — would mix two documents; the piece editor already works and is tested.

## Consequences

- Memory: up to 100 project snapshots; designs are shared by reference between snapshots when unchanged.
- ADR-0047's consequence "project-level changes have no undo" is replaced by this ADR.

## Questions and answers (2026-10-24; recommended answers auto-accepted on the user's instruction)

1. *Should undo cover the project as a whole, including run parts and merges?* — **Yes, every project change.**
2. *Should a project edit and the edits made inside a piece share one history?* — **No: two histories; leaving the
   piece editor records one project step.**
3. *Should history survive closing the app?* — **No, session only, like the piece editor.**
4. *Keep the confirmation dialogs for Remove and Merge?* — **Yes, keep them; change their wording.**
