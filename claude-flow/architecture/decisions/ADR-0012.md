## Context

A bug in placement code could emit overlapping parts or a layout outside the sheet. If the same code both produced
and checked the layout, the check would share the bug. The user explicitly asked that every layout be validated
before it is shown or exported.

## Decision

`validateResult(project, result)` in `src/engine/validate.ts` is written **independently** of the placement and
splitting routines. It re-derives usable regions, walks every cut tree reconstructing child rectangles, checks
kerf, containment, duplicate placements, source geometry/material/thickness/grain equality, per-source
consumption vs quantity, that every requested instance is placed or listed as unplaced exactly once, and that
area is conserved (`gross = parts + trims + kerf + recoverable + unrecoverable`). `optimizeProject` sets
`result.valid` from it and the React view/export path refuses invalid results. Cached `lastResult` is re-validated
on load and discarded if invalid.

## Alternatives considered

- **Trust the generator, test it heavily** — rejected: tests cover fixtures, the validator covers every real job.
- **Validate only in tests** — rejected: production inputs (imported workbooks, hand-edited JSON) are far more varied than fixtures.

## Consequences

- Every new geometric feature is implemented twice (generator + validator), deliberately without shared helpers for the core checks.
- Validation cost is O(nodes); acceptable at workshop scale.
- A validator failure is surfaced to the user as a hard error with the `errors` list, never swallowed.

## Evidence (repository files)

- `src/engine/validate.ts` — top comment "Intentionally independent from the placement/splitting routines."
- `src/engine/optimize.ts` — imports `validateResult` and sets `valid/errors`.
- `src/db/migration.ts` — discards invalid cached results on migration.
- `docs/architecture.md` — "The independent validator checks cut trees, dimensions, materials, grain, kerf, and conservation before the React view/export path can use results."

## Compliance check

`validate.ts` imports nothing from `guillotine.ts` or `optimize.ts`; `grep -n "validateResult" src/` shows it called in `optimize.ts`, `migration.ts` and the export/render path.
