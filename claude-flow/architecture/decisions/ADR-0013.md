## Context

A 1.5 s search on the main thread freezes a phone UI and can trigger "page unresponsive" prompts.

## Decision

`src/engine/optimizer.worker.ts` receives `{id, project}` and posts `{id, result}` or `{id, error}`. The engine
module is pure (no DOM, no storage) so it can be imported by the worker, by Node kernel tests and by the main
thread for validation.

## Alternatives considered

- **Chunked main-thread search with `setTimeout`** — rejected: complicates the algorithm and still janks.
- **WASM port** — unnecessary at current job sizes; purity preserved so it stays possible.

## Consequences

- Engine code must stay free of browser globals; `tests/*.node.test.mjs` enforce this by running under plain Node.
- Messages are correlated by `id`; the UI must ignore stale responses.

## Evidence (repository files)

- `src/engine/optimizer.worker.ts` (7 lines) — message handler.
- `package.json` — `"test:kernel": "node --experimental-strip-types --test tests/*.node.test.mjs"`.
- `docs/architecture.md` — "A Web Worker imports the deterministic seeded heuristic engine."

## Compliance check

`npm run test:kernel` runs without a DOM; the worker file has no imports from `src/components` or `src/db`.
