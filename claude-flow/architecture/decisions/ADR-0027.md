## Context

The core cut editor must load fast on a mid-range Android phone over a workshop Wi-Fi; three.js (~946 KB) and
ExcelJS are needed only on demand. ADR-0002 forbids runtime CDN fetches.

## Decision

`@react-three/fiber`/`three` components and `exceljs` are dynamic imports behind user actions; the chunks are still
part of the Pages build and precached by Workbox (8 MB per-file cap). No asset is loaded from a third-party origin.

## Alternatives considered

- **Load three.js eagerly** — rejected: doubles initial payload for a feature many sessions never open.
- **CDN for three.js** — rejected: offline-first and ADR-0002.

## Consequences

- Chunk size is monitored in handoff notes; a new heavy dependency must be lazy and justified in `delivery/dependencies.md`.

## Evidence (repository files)

- `src/import-export/excel.ts` — "Code-split on demand."
- `AGENTS.md` — "Viewer is lazy-loaded, capped to 40 distinct part rows"; `docs/licences.md` — "All assets are bundled locally; no runtime CDN".
- `vite.config.ts` — `workbox.maximumFileSizeToCacheInBytes: 8*1024*1024`, `globPatterns`.

## Compliance check

`npm run build` output lists a separate chunk for three/fiber; `index.html` and `dist/` contain no external `<script src>`.
