# Change and disagreement protocol

Trigger: new user direction, architecture conflict, vendor dimension mismatch or failed validation.

Identify old and proposed decision and sources. Apply precedence: new explicit user instruction, confirmed consensus, accepted ADR/spec, executed implementation/tests, earlier discussion, unconfirmed proposal. Keep superseded decisions with lineage. Mark contradictions unresolved when neither source can authoritatively win. Never merge supplier ABS-inclusive final sizes directly into saw-cut sizes without signed-off transform. Architecture authority records any shared-model change. Independent verifier confirms scope, tests and migrations.
